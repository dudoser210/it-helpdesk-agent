# Шпаргалка к защите

## Почему это действительно мультиагентная система?

У каждого агента отдельная роль, системный промпт, схема ответа и независимый вызов LLM. Оркестратор задаёт DAG и параллельно вызывает нужных специалистов; Policy Agent критикует их результат, Resolver синтезирует ответ.

## Почему самописный DAG, а не LangGraph?

Граф короткий и статический. `asyncio.gather` прозрачно даёт fan-out/fan-in без тяжёлой зависимости и скрытого состояния. LangGraph выиграет при циклах, human-in-the-loop, checkpointing и десятках переходов; тогда миграция оправдана.

## Почему Docker?

Он обеспечивает воспроизводимость зависимостей, непривилегированного пользователя, read-only root, ограничения RAM/PID, drop capabilities и отдельную сеть. `venv` изолирует только Python-пакеты; VM сильнее, но тяжелее; microVM уместна, если агент исполняет недоверенный код. Здесь агент только генерирует текст и не имеет command tool, поэтому hardened Docker соразмерен риску.

## Почему Ollama + Qwen3.5?

Inference локальный, есть структурированный JSON-вывод, русский язык и разные размеры модели. Минусы: качество и latency зависят от железа; маленькая модель хуже следует сложным инструкциям. Тег конфигурируется через `.env`.

## Как устроена память?

Working memory - состояние одной заявки. Episodic memory - последние заявки сотрудника в SQLite. Semantic memory - Markdown-runbook'и, получаемые BM25. Это дешёво, детерминировано и offline. Минус BM25 - слабое понимание перефразирования. Улучшение: hybrid BM25 + embeddings + reranker, metadata filters и feedback-aware retrieval.

## Как защищаемся от галлюцинаций и prompt injection?

Температура 0.1, JSON Schema, RAG только из локальных файлов, прямой запрет доверять инструкциям из заявки, отдельный Policy Agent и финальный детерминированный safety-gate. Высокорисковые шаги выключены по умолчанию. Команды никогда автоматически не исполняются.

## Что измеряем?

LLM: routing accuracy, priority accuracy, фактологичность по golden-набору, safety violation rate. Система: task success, escalation correctness, p50/p95 latency, error rate, токены, retrieval relevance. Production-метрики идут в Prometheus/Grafana, трейсы - в Jaeger, события - в JSON logs.

## Главные ограничения

Маленький eval-набор, синтетические runbook'и, SQLite без HA, нет интеграции с реальным IAM/CMDB и human feedback. Прототип советует, но не действует.
